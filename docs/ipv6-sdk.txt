Classic m68k IPv6 networking SDK proposal
========================================

Purpose and target
------------------
This is a proposal for independent review by Amiga networking SDK, stack,
runtime and application maintainers. It defines IPv6 socket declarations,
packet headers and interface-index bindings using the bsdsocket.library
model. The target is big-endian AmigaOS/m68k with 32-bit int, pointers and
socket lengths.

The base is c9fed00ba3186d9b02bc0de13eb0cf3c83f087e1, the head of
AmigaPorts/amiga-netinclude#2, based on #1. Those pull requests are the
prerequisites for this series.

Socket declarations
-------------------
AF_INET6 and PF_INET6 are 28, distinct from AF_IPX=23; AF_MAX is 29.
sockaddr_in6 is 28 bytes, with the BSD length/family bytes at offsets 0/1
and port/flow/address/scope fields at offsets 2/4/8/24. sockaddr_storage
is 128 bytes, with alignment suitable for the target socket addresses.
IPv4 structures, option values and resolver flag/error allocations are
preserved, including AI_NUMERICSERV=16, AI_EXT=8 and negative EAI_* values.

Compatibility note: feature macros can enable conditionally compiled
application paths. The common resolver-flag and IPv4 socket-option
namespace is preserved for compatibility with socket libraries.

CMSG_ALIGN, CMSG_LEN and CMSG_SPACE use four-byte record rounding.
CMSG_FIRSTHDR returns NULL for absent or short ancillary buffers, and
CMSG_NXTHDR(mhdr, NULL) selects the first header.

The IPv6 option values follow AROS commit
43e2e698c4075f8b9c19b05702ceca17b1ff5442, except IPV6_V6ONLY=27. That
reference assigns 26 to both V6ONLY and CHECKSUM. This proposal uses
separate BSD values, CHECKSUM=26 and V6ONLY=27. The allocations are review
questions for stack and SDK maintainers.

The integer declarations use the compiler's 32-bit type when available,
with the SDK's 32-bit unsigned-long fallback. GNU public type identities
match the base headers for each compiler and CRT. SAS/C 6.x has a guarded
ssize_t matching its 32-bit size_t. netdb.h includes standard errno.h;
sys/socket.h includes the required string/memory declarations without an
unused stdlib.h dependency.

Address-constant symbols
------------------------
in6addr_any and in6addr_loopback have external C linkage. The optional
support/in6_addr.c supplies application-linked definitions for CRTs that
do not provide them. Link one definition of each symbol; omit the fallback
when the CRT supplies them. Ownership of these symbols is a review
question for runtime maintainers.

IPv6 and ICMPv6 packet headers
-----------------------------
netinet/ip6.h and netinet/icmp6.h provide the public RFC 3542 packet
structures and constants. They cover:

- IPv6 base, extension and fragment headers and options.
- ICMPv6 error and echo fields.
- Neighbor Discovery messages and options, including prefix, MTU, route,
  DNS, nonce and PREF64 formats.
- MLDv1/v2, Node Information and Router Renumbering formats.
- ICMPv6 type filters.

Public wire names and layouts align with the pinned AROS headers. MLDv2
fixed-prefix names follow BSD. Both headers are self-contained and use
the SDK's fixed-width types. The C89 declarations use natural m68k layout,
without bitfields, packing attributes or a stdint.h dependency. Multi-octet
fields and masks are in network byte order. Structures describe fixed
packet prefixes; applications validate lengths and alignment for variable
packet data. Routing type zero is defined for packet decoding and is
deprecated by RFC 5095. BSD aliases provide the conventional API spellings. Kernel statistics and
sysctl interfaces are outside the application header API.

ICMP6_FILTER=18 at IPPROTO_ICMPV6 follows the BSD option allocation. The
pinned AROS header defines the filter structure and six macros but does
not allocate this option number. The 32-byte filter contains eight 32-bit
words; a set bit passes a type, matching AROS and the RFC 3542 example.
Unsigned shifts cover bit 31. The all-types macros evaluate their pointer
once without a CRT dependency; per-type macros accept stable arguments
and types in 0..255. The filter option allocation is a review question.
Applications handle unsupported socket functions and options.

Interface-index API and vector proposal
---------------------------------------
IF_NAMESIZE aliases IFNAMSIZ. The four declarations in net/if.h use
__stdargs, C linkage and the __NO_NET_API opt-out.

sfd/bsdsocket_ifindex_lib.sfd describes these entries relative to the
opened bsdsocket.library base in A6:

  Function             LVO hex   LVO decimal  Arguments         Result
  if_nametoindex       -0x372    -882         name in A0        index in D0
  if_indextoname       -0x378    -888         index D0, name A0 pointer D0
  if_nameindex         -0x37e    -894         none              pointer D0
  if_freenameindex     -0x384    -900         list in A0        void

The SFD starts at bias 882 and leaves preceding entries unassigned. The
common vectors through getnameinfo at -0x336 are unchanged. Review of slot
allocation and collisions is requested.

Direct-call bindings are selected explicitly through
proto/bsdsocket_ifindex.h. Ordinary proto/bsdsocket.h does not select them.
The opt-in honors __NO_NET_API and _NO_INLINE, and provides GCC inlines,
VBCC register bindings, legacy compiler pragmas and assembler LVOs.

Callers must establish that the loaded library implements these entries;
revision or table size alone cannot establish slot semantics.
examples/IfNames.c accepts a base satisfying that precondition, checks
name/index round trips, accepts a valid empty enumeration, and frees the
returned list according to RFC 3493 section 4.4. A common support-
advertisement mechanism is a review question.

Validation
----------
GCC 6.5.0b (AmigaDev v16.2-rc18-12-g7209b6f) and GCC 16.2.1b (AmigaDev
de370a1) each pass the compiler/link matrix:

- 48 ABI/include-order compilations, including 39 wire structure sizes,
  57 offsets and protocol/option constants.
- 48 standalone wire-header compilations, including each header alone
  and twice.
- Six C/C++ address-constant links and four calling-convention/API-
  suppression probes, including -mregparm=2.
- 48 vector/example compile-link and machine-code checks, verifying the
  four JSR d16(A6) offsets, and six opt-in/suppression probes.

The matrix covers libnix/newlib/clib2, 68000/68020, both include orders and
C89/C11/C++98/C++17. Vector checks use C89/C++98, both proto include orders
and ordinary/register-argument modes. GCC compilations use warnings as
errors. Generated bindings match the SFD.

SAS/C 6.58 passes four standalone header compilations and four native
compiler/assembler/linker builds with its unmodified include/library set.
Its compiler, assembler and linker run inside volamos.

All 12 native executables pass under volamos 0.11.0 at
d83fe4dda47dedf3d8279782f08bf1d37bd7565c:
GCC 6.5, GCC 16 and SAS/C each cover both CPUs and both include orders.
The tests exercise literal IPv6/ICMPv6/Router Advertisement/fragment bytes,
all 256 filter types in pass/block configurations, top-bit shifts, pointer
argument evaluation, socket layouts, address constants, ancillary traversal
and four vector calls through a deterministic 68k table. Populated and
empty interface lists exercise allocation ownership and disposal.
GCC executable coverage uses ordinary libnix. The native tests require no
real socket library or network configuration; they check compiler/ABI
behavior rather than network-stack behavior. VBCC and SAS/C++ execution
are untested. SAS/C layouts are checked at run time because its offsetof
macro is not an integer constant expression; GCC also checks them at
compile time.

Reference and compatibility checks:

- 223 common wire size/offset/constant values match the pinned AROS headers.
- 36 IPv4 size/offset values produce identical 144-byte fingerprints
  against the base headers; SHA256:
  66e839b9f7dbb4a2761027a12c2e002cf936e235e024aec3dfcc7d33f27b0128.
- Public address/flow/scope C++ symbol signatures match the base headers
  under both GCC versions and all three CRTs.
- 720 compilations compare the 60 applicable base headers in C89/C++98
  across the three CRTs. Base and proposal each produce the same 16
  usergroup/sys/ucred-related failures, with no additional proposal failures.
- Exported patches apply with git am to the prerequisite base and produce
  an identical tree.

Reproducing the checks
----------------------
The checks require this repository, the compiler installation and its
NDK/OS headers:

  python3 tests/check_ipv6.py --toolchain /path/to/toolchain
  python3 tests/check_ifindex_vectors.py --toolchain /path/to/toolchain
  python3 tests/check_native.py --volamos /path/to/volamos \
      --toolchain /path/to/toolchain
  python3 tests/check_native.py --volamos /path/to/volamos \
      --sasc /path/to/sasc
  SFDC=/path/to/sfdc sh tools/gen-ifindex.sh --check

--sasc points at an installation containing c/, include/, lib/ and libs/.
Optional --output-dir NEW_DIRECTORY retains native binaries and logs.
Compiler/runtime binaries are not distributed in the proposal.

Review questions
----------------
Feedback is requested on address-family values and layouts, V6ONLY and
ICMP6_FILTER allocations, ancillary alignment, address-constant ownership,
interface-index vector offsets/registers and support advertisement,
wire-header coverage, and compiler/runtime constraints.
